## 二、架构描述（本轮全部改动点）

### 表结构
- 零新列、零 ALTER。所需列均已在 `scr-backend/src/index.js` 建表区：
  - `scr_groups.allow_chain` / `scr_groups.allow_vote`：TINYINT(1) 默认 1（普通成员发起接龙/投票的分别开关）。
  - `scr_groups.show_typing`：TINYINT(1) 默认 0（群成员输入状态展示开关）。
  - `scr_messages.client_msg_id` + 唯一索引 `(user_id, client_msg_id)`（幂等）。
- 数据源五表不变：`scr_group_chains` / `scr_group_chain_entries`（唯一约束一人一条）/ `scr_group_votes` / `scr_group_vote_options` / `scr_group_vote_records`。消息壳（scr_messages）与数据源记录同事务落库。

### 消息类型与 payload（scr_messages.message_type）
- 0~7 既有；8 CHAIN `{chainId,title,content}`；9 CHAIN_ENTRY `{chainId,entryId,title,content}`；10 VOTE `{voteId,title,description,multiple,anonymous,endsAt,options[{id,label}]}`。
- socket `send-message` 对 type 8/9/10 一律拒绝（`INVALID_MESSAGE_TYPE`），消息壳必经 REST 专用接口的校验链。

### 接口
- `POST /api/groups/:groupId/chains`（发 type8）｜`POST /api/chains/:id/join`（发 type9，重复 409）｜`GET /api/groups/:groupId/chains`（含 joined）
- `POST /api/groups/:groupId/votes`（发 type10）｜`POST /api/votes/:id/ballot`（发布人 403；改票覆盖；相同集合 409）
- close 两接口：任意身份 410 IRREVOCABLE。
- 发布人视角：所有返回 vote 的接口对 creator 附加 `result{totalVoters,options[{count,voters[]}]}`，匿名不脱敏。
- `GET /api/messages/browse?scope=public|group|private&groupId=&peerId=&types=&keyword=&page=&pageSize=20`（分页浏览/搜索二合一，hasMore 翻页）。
- 群设置：`PUT /api/groups/:groupId/settings`（allow_chain/allow_vote，群主/管理员），groupFeature settings 接口管 show_typing。

### socket 事件 / Redis
- 扇出全部走既有 Redis Streams 架构：`broadcastProducer.enqueue(room,event,payload)` → Stream `broadcast_stream` → consumer 按房间扇出；产品代码无 io.to/io.emit。房间 `group_<groupId>`。
- 事件：`message-received`（挂 chain/vote 附加字段，前端按消息 id upsert 去重）、`group-chain-created`、`group-chain-updated`（含全量 entries）、`group-vote-created`、`group-vote-updated`（结果实时广播，匿名 voters 脱敏，发布人 result 不脱敏）。
- 未读水位：消息壳落库后同步 `scr:max_msg_id:group:<gid>`。

### 权限
- 普通成员：发起接龙/投票受 allow_chain/allow_vote 限制（403）；参与接龙、投票不限（投票不能投发布人的自己的票）。群主/管理员发起不受限、可改开关。撤销无人可用。

### 开关存储
- 用户级（typing 自显开关等）在 scr_users 注册信息项，self 接口下发；群级 allow_chain/allow_vote/show_typing 在 scr_groups；前端依据开关决定是否发事件（关=前端不发）。

### 限流 / 幂等 / 内容过滤
- 三个发送接口接入 `checkRateLimit`：10 次/10s + 40 次/60s（`scr:rate_limit:<uid>:short|long`），429 带 retryAfter。
- `clientMsgId`（≤64）幂等：事务内命中重复整体回滚，回 200 `duplicate:true` + 首包数据；未加幂等列的存量库自动降级。
- 长度校验（标题 100/内容 1000/选项 2~20）+ payload 序列化 ≤10000 字符。
